# Checklists: Product & Strategy
Format follows Gawande's *Checklist Manifesto*: short, killer items only, at defined pause points.
DO-CONFIRM = do the work, then confirm every item.

## DoD for any Product T1/T2 item (DO-CONFIRM)
- [ ] Traces to a named exit criterion or a logged scope change
- [ ] Persona named; no generic "users"
- [ ] Cost impact stated (tokens / minutes / Founder time)
- [ ] Assumptions it relies on are listed with IDs
- [ ] Return written in the RETURN format with evidence paths

## Gate checklist (used blind at every T3)
- [ ] Every exit criterion of this milestone has an evidence path; none is E0
- [ ] Kill criteria evaluated explicitly (triggered / not triggered, with evidence)
- [ ] Scope changes this milestone ≤ 2, or Founder-approved
- [ ] Unit economics updated with measured numbers (from M2)
- [ ] Next milestone's scope written, with exit and kill criteria
- [ ] PR/FAQ still true; any FAQ answer invalidated by evidence is rewritten
- [ ] Top 3 risks for next milestone named
- [ ] One checkable prediction recorded

## Pre-mortem prompt (Product perspective)
"We failed because we built the wrong thing / for the wrong person / at the wrong cost." List ≤ 7 concrete ways.
