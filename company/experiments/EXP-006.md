- **Prior work:** `experiments/E6.md` is exploratory (E1 at most) and is **not** evidence for this experiment. Its finding (ASS default `Encoding: 1` gives LTR base direction; `Encoding: -1` fixes mixed RTL/LTR order) is used here only to fix a render parameter in advance.

## 1. Question
Does our FFmpeg 6.1.1 + libass path, with the parameters fixed below and the font Noto Sans Arabic, render all 10 Arabic test strings of `company/positions/04-creative/ARABIC_QA.md` correctly, as judged by creative-lead?

## 2. Hypothesis (falsifiable)
- **H1:** All 10 strings AR-01..AR-10 are judged correct by creative-lead, and zero Sev-1 defects are recorded.
- **H0:** At least one string is judged not correct, or at least one Sev-1 defect is recorded.
- What we would expect to see if H1 is wrong: disconnected letters, lam-alef rendered as two glyphs, reversed word order in mixed Latin/digit strings (AR-04, AR-05, AR-10), mis-stacked harakat (AR-07), unmirrored brackets (AR-08), broken tatweel (AR-09), or tofu boxes from font fallback.

## 3. Variables
- **Independent:** none varied. This is a single-condition acceptance test of one fixed configuration.
- **Dependent (per string i = AR-01..AR-10):**
  - `correct_i` ∈ {1, 0}, recorded by the judge (definition in §6).
  - `sev1_i` = number of Sev-1 defects recorded for string i.
  - Aggregate: `N_correct = Σ correct_i` (0..10); `N_sev1 = Σ sev1_i`.
- **Controlled (held constant, values fixed in §5.2):** renderer (ffmpeg 6.1.1-3ubuntu5 CLI, `ass` filter, `shaping=complex`), libass 0.17.1, HarfBuzz 8.3.0, FriBidi 1.0.13 (versions as seen on 2026-11-22; captured again at run time), font file, font size, colours, outline, alignment, margins, wrap style, `Encoding: -1`, frame size and colour, output format (PNG, RGB), hardware (Codespace, CPU only). No model, no LLM, no randomness: seeds not applicable.

### 5.2 Fixed render parameters (do not change)
| Parameter | Value |
|---|---|
| Frame | 1080 × 1920, solid neutral grey `0x808080`, generated by lavfi `color`, 1 s at 30 fps; first frame (t = 0) exported |
| Output | PNG, `rgb24`, one file per string: `render/frames_check/AR-01.png` … `AR-10.png` (repo root) |
| ASS files | `render/frames_check/AR-01.ass` … `AR-10.ass`, UTF-8 **without BOM**, LF line endings, one Dialogue line each |
| `[Script Info]` | `ScriptType: v4.00+`, `PlayResX: 1080`, `PlayResY: 1920`, `WrapStyle: 0`, `ScaledBorderAndShadow: yes` |
| Style name / font | `Default`, Fontname `Noto Sans Arabic` (Regular, Bold = 0, Italic = 0) |
| Font size | `72` |
| Colours | PrimaryColour `&H00FFFFFF` (white), SecondaryColour `&H000000FF`, OutlineColour `&H00000000` (black), BackColour `&H80000000` |
| Border / shadow | BorderStyle `1`, Outline `4`, Shadow `0` |
| Scale / spacing / angle | ScaleX `100`, ScaleY `100`, Spacing `0`, Angle `0` |
| Alignment / margins | Alignment `5` (middle centre), MarginL `60`, MarginR `60`, MarginV `60` |
| Encoding | **`-1`** (libass automatic base direction; fixed from the E6 exploratory finding) |
| Dialogue | `Dialogue: 0,0:00:00.00,0:00:05.00,Default,,0,0,0,,<string verbatim>` with no override tags and no escaping (none of the 10 strings contains `{`, `}` or `\`) |

### 5.3 Steps
1. Capture the environment into `render/frames_check/ENV.txt`: `ffmpeg -version | head -3`, `ffmpeg -hide_banner -filters | grep -w ass`, `dpkg -l libass9 libharfbuzz0b libfribidi0 fonts-noto-core | grep ^ii`, `fc-match "Noto Sans Arabic"`, `fc-match -v "Noto Sans Arabic" | grep file`, `uname -a`, `nproc`, date (UTC).
2. Write the 10 `.ass` files exactly as in §5.2, with the string copied programmatically from `ARABIC_QA.md` (never retyped). Verify code point count and SHA-256 prefix against the §4 table; write the check output to `render/frames_check/strings_check.txt`.
3. For each ID in AR-01..AR-10, run (from repo root), appending stdout+stderr to `render/frames_check/render.log`:
   ```
   ffmpeg -hide_banner -y -f lavfi -i "color=c=0x808080:s=1080x1920:r=30:d=1" \
     -vf "ass=filename=render/frames_check/AR-XX.ass:shaping=complex,format=rgb24" \
     -frames:v 1 render/frames_check/AR-XX.png
   ```
4. Check `render.log` for libass font-fallback or "Glyph not found" warnings; record any in the results. Record SHA-256 of every PNG and `.ass` in `render/frames_check/SHA256SUMS`.
5. Engineering does **not** judge the images and does not show them to the judge with any commentary.
6. Judge (creative-lead, H-0007): open each PNG at 200% zoom, with the verbatim reference string from §4 alongside. For each string, check all categories: shaping/joining, RTL word and letter order, digits (direction and form), Latin words (order and integrity), lam-alef ligature, diacritics placement/stacking, brackets/quotes mirroring, tatweel/kashida, punctuation (، ؟ ٪ –), clipping/cut-off, missing glyphs (tofu). Record per string: `correct` (yes/no), each defect with category + severity (Sev-1/2/3 per ARABIC_QA.md), and a one-line note.
7. Research writes `company/experiments/EXP-006-results.md` (SOP-R3), including the per-string table, `N_correct`, `N_sev1`, the verdict, ENV.txt contents and all deviations.

## 6. Metrics and thresholds (set NOW, never changed after)
**Definition of "correct" for one string (operationalisation of the Founder's rule):** creative-lead judges string i correct (`correct_i = 1`) only if it records **no Sev-1 defect, no Sev-2 defect, and no defect of any severity in the property that string is designed to test** (column "What it tests"; e.g. a wrong `؟` in AR-06 or wrong `،` in AR-02 makes that string not correct even though it is Sev-3). Sev-3 defects in properties a string does not test are recorded but do not by themselves make it incorrect. Tofu / missing glyphs and clipped text count as Sev-1 (missing shaping / caption cut).

| Metric | Threshold for "pass" | Threshold for "kill" (= FAIL) |
|---|---|---|
| `N_correct` (strings judged correct, of 10) | = 10 | ≤ 9 |
| `N_sev1` (Sev-1 defects, all strings) | = 0 | ≥ 1 |
| **Verdict** (Founder-fixed rule) | **PASS iff `N_correct` = 10 AND `N_sev1` = 0** | **FAIL otherwise** |

There is no "neither" zone: the rule is binary. A run that violates §5 in a way listed in §8 as invalidating is reported as **INVALID** (no verdict), not as PASS.

## 7. Analysis plan
- Count-based, no statistics: n = 10 fixed strings chosen by Creative to cover the known Arabic failure classes; the decision changes on a single failure (smallest effect that changes the decision = 1 string), so no sampling argument applies.
- No ties or outliers: each string is one deterministic render.
- Evidence level if PASS with no validity-affecting deviation: **E2** (preregistered metric, measured on our fixed test set; there is no golden-video set involved, so the claim is limited to these 10 strings in this style). If a validity-affecting deviation occurs, downgrade one level (SOP-R3.3).
- On FAIL: record which strings and categories failed; the conclusion is "FFmpeg + libass with these parameters does not pass", nothing broader. Any fix (other font, other `Encoding`, pre-processing, Remotion) is tested under a **new EXP id** that references EXP-006. EXP-006 is never edited or re-run with changed parameters.

## 8. Deviations policy and threats to validity
**Deviations (any change from §5) are listed in the results, never hidden.**
- **Invalidating (verdict = INVALID):** different font file resolved, any §5.2 parameter changed, string fingerprint mismatch, a PNG missing, frame size not 1080×1920, judge not creative-lead, judging done without 200% zoom or without the reference string.
- **Re-execution rule:** if an execution error (e.g. a wrong path, a missing directory) is found **before any PNG has been shown to the judge**, Engineering may re-run the identical §5 procedure, max 2 times (company retry rule), logging each attempt. **Once any PNG has been judged, the result stands**; no re-render, no re-judging until it passes.
- **Non-invalidating, recorded:** library patch versions different from those in §3 (record them), extra log warnings that are not font fallback.

**Threats to validity**
| Type | Threat | Mitigation |
|---|---|---|
| Construct | The judge is an LLM agent reading images; it may miss subtle shaping or mark-placement errors a native reader would see. | Fixed checklist per category; 200% zoom; reference string alongside. Recommend (non-decisive, does not change the verdict) a Founder spot-check of AR-02, AR-05, AR-07, AR-08 recorded in the results. |
| Construct | Single judge, no agreement measure. | Accepted for an acceptance test of a deterministic render; noted as a limit of the evidence. |
| Construct | "Correct" leaves room for judgement on Sev-3 issues. | Operational definition fixed in §6 before rendering. |
| Internal | Silent font fallback (glyphs from another font) would test the wrong font. | Precondition §5.1.2, `fc-match` capture, log check in step 4. |
| Internal | Strings altered by copy/paste (invisible marks, normalisation). | Programmatic copy + fingerprint check (§4, step 2). |
| Internal | Judge sees images before the rule is fixed / reruns until pass. | This file is LOCKED before any render; re-execution rule above. |
| External | Single line on plain grey does not cover real Shorts: word-by-word karaoke (`\k`), line wrapping across lines, bold display fonts (Cairo, Tajawal), video backgrounds, Remotion. | Claim is limited to this configuration. Karaoke, wrapping and other fonts need their own EXP ids. |
| External | `src/render` currently derives styles from `timeline.json`; it may differ from §5.2 (e.g. Bold, sizes). | The PASS applies to the §5.2 parameters; Engineering should confirm `src/render` writes `Encoding: -1` and `shaping=complex` (it does as of 2026-11-22). |
