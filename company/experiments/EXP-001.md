## 1. Question
On our own Lebanese-dialect footage (with rights), how accurate are the transcripts and word timestamps from faster-whisper 1.2.1 with `large-v3` and with `large-v3-turbo` (CPU, int8, fixed decoding parameters in §3), measured against blind human reference transcripts and human-marked word boundaries, and does either model meet the thresholds in §6?

## 2. Hypothesis (falsifiable)
Evaluated per model (M ∈ {large-v3, large-v3-turbo}).
- **H1(M):** On the Lebanese pool (§4), `WER_LB(M)` ≤ the pass threshold **and** `P90_BE(M)` ≤ 150 ms.
- **H0(M):** `WER_LB(M)` > the pass threshold **or** `P90_BE(M)` > 150 ms.
- The experiment as a whole supports adoption if H1 holds for at least one model. The selection rule among passing models is fixed in §7.

## 3. Variables

- **Dependent (formulas in §6):** `WER_LB`, `CER_LB`, `P90_BE`, `MED_BE`, `HALL_RATE`, `RTF`; diagnostics `WER_MSA`, `WER_LATIN`, per-clip WER/CER.
- **Controlled (identical for both models):**
  - Software: faster-whisper 1.2.1, ctranslate2 4.9.0, ffmpeg 6.1.1 (versions as installed in the Codespace, 2026-11-22; recorded again in `ENV.txt` at run time). Python version recorded.
  - Decoding: `device="cpu"`, `compute_type="int8"`, `language="ar"` (forced), `beam_size=5`, `word_timestamps=True`, `vad_filter=True` with faster-whisper 1.2.1 default VAD parameters, every other `transcribe()` argument at the faster-whisper 1.2.1 default (including the temperature fallback list).   - Audio: each clip decoded by the ffmpeg CLI to 16 kHz mono 16-bit PCM WAV exactly as `src/ingest` `load_audio` does; the same WAV (sha256 recorded) is given to both models and to the human annotators.

No clip currently in the manifest is used or named here (all are rights `NONE` / UNVERIFIED). `quarantine/` and `data/heldout/` are never used.

| Requirement | Value |
|---|---|

| MSA control (diagnostic only) | ≥ 1 clip of Modern Standard Arabic, ≥ 2 min of speech. Not part of the decision metrics; used to separate "dialect is hard" from "audio/instrument is broken". |
| Clip length | 60–300 s each; if a source is longer, a contiguous 300 s window is chosen by Creative **before any ASR output exists** and recorded as start/end in the manifest. |
| Speakers | ≥ 2 distinct speakers across the Lebanese pool; no single speaker > 70% of Lebanese-pool speech. |
| Audio quality | Manifest audio score ≥ 3 (1–5 scale). Clips below are excluded, not down-weighted. |
| Held-out | Not used. A held-out replication (E3) is for a later gate, by Assurance only. |

Sample-size rationale: the decision changes if pooled WER moves by about 10 percentage points (pass vs kill band, §6). With ≥ 1,200 reference words, the binomial standard error of a pooled WER near 35% is ≈ 1.4 pp, so word-level noise is far below the band; the dominant uncertainty is between clips, which is why ≥ 4 clips and ≥ 2 speakers are required and a clip-level bootstrap CI is reported (§7). For boundaries, 30 sampled words per Lebanese clip gives ≥ 120 words / ≥ 240 boundary errors, enough to estimate a P90 with about 24 observations above it.

## 5. Procedure (Engineering executes in a later brief; human references are produced first)
### 5.1 Preconditions (all must hold; otherwise stop, do not transcribe)
1. Every clip meets §4; clip IDs, rights IDs and window start/end are written into §4 of the LOCKED file.
2. Reference transcripts and boundary annotations (5.2, 5.3) exist, and their sha256 values are committed **before** any ASR output for these clips exists (Assurance checks the commit order).
3. The normalisation function passes all test vectors in §6.2 (`exp001_norm_test.txt`, exit 0).
4. Both models are downloaded and their revisions match the pins (E1).

### 5.2 Reference transcripts (human; blind to ASR)
1. **Who transcribes:** a native Lebanese-Arabic speaker named at lock (default: the Founder; open question O2). An LLM position cannot be the transcriber: no LLM listens to the audio (I-3 spirit, and no audio input exists in our tooling). creative-lead owns the spelling guide and checks the text for consistency only.
2. **Blindness:** the transcriber has never seen any ASR output (including E1 or `src/ingest` output) for these clips, and declares this in writing in the results file. Transcription is from audio only (any player; playback speed free).
3. **Spelling policy (from `company/positions/04-creative/ARABIC_QA.md` "Dialect policy"):** spelling follows the speaker; Lebanese stays Lebanese (e.g. "شو"، "هيك"، "منيح"، "كتير"); dialect is never "corrected" into MSA. English and French words stay in Latin script in their standard spelling ("iPhone", "merci"). Numbers are written as digits when the speaker says a number ("250"), in words otherwise. No diacritics needed (they are stripped anyway).
4. **Spelling guide:** before transcription starts, creative-lead writes `EXP-001-spelling-guide.md` (≤ 1 page): conventions for frequent Lebanese function words and clitics (e.g. whether "على" before a definite noun is written "عال…"), and a list of at most 30 **orthographic** variant pairs that are the same spoken word and count as equal (e.g. "هلق" ≡ "هلأ", both written for the same spoken glottal-stop form). Rule: a pair is admissible only if both spellings represent the same pronunciation; an MSA form of a dialect word (e.g. "كثير" for spoken "كتير") is **not** admissible and counts as an error, because a caption in MSA violates the dialect policy. The guide is frozen (sha256 committed) before any ASR output exists.
5. **Non-speech marking:** the transcriber marks every non-speech interval ≥ 1.0 s (silence, music, laughter, applause) as `[start, end]` in seconds in `EXP-001-nonspeech.json`.
6. Unintelligible stretches are marked `[؟؟]` with start/end and **excluded** from all metrics for both models (the excluded duration is reported; > 10% of a clip's speech excludes the whole clip and is a recorded deviation).
7. **Reference reliability (recommended; O3):** a second native speaker independently transcribes ≥ 1 Lebanese clip (≥ 2 min). Inter-transcriber WER (normalised as §6.2) is reported. If it exceeds 12%, the reference is too noisy for a 10 pp decision band and the result is reported as INCONCLUSIVE regardless of the model numbers.

### 5.3 Human word boundaries (for timestamp accuracy)
1. After the references are frozen, code draws, per Lebanese clip, 30 reference word positions at random (seed `20261122`) from words that are (a) not adjacent to an excluded `[؟؟]` stretch and (b) at least 2 Arabic letters long. Drawing happens on the reference only, so it does not depend on ASR output.
2. The annotator (the transcriber or a second person, O2) marks start and end of each drawn word on the 16 kHz WAV in Praat or Audacity (label track), at ≥ 10 ms visual resolution, without seeing any ASR timestamp. Output: `EXP-001-boundaries.csv` (clip, ref_index, word, start_s, end_s).
3. In analysis, a drawn word is used for model M only if the §6.1 alignment matches it to a hypothesis word of M with the **same normalised form** (a correct word). The number used per model is reported; if fewer than 20 of 30 match for a clip under a model, that clip's boundary metrics are reported but marked low-n.

### 5.4 Steps (Engineering)
1. Record `ENV.txt` (package versions, model repo + revision, ffmpeg version, CPU model, `nproc`, Python), instrument sha256 (`experiments/exp001_asr.py`, derived from `e1_asr.py` with the §6 normalisation), and the reference/guide/boundary sha256 values.
2. Decode each clip window to WAV (§3); record sha256.
3. For each clip, for each model in the fixed order: `ctranslate2.set_random_seed(0)`, transcribe with the §3 parameters via the same `transcribe()` code as `src/ingest`, write the transcript to `out/exp001/<clip>/<model>.json` and copy it to result storage named at lock (E4). Record runtime (wall clock around `transcribe()`, model load included, download excluded) and audio duration.
4. Determinism check: re-run `large-v3-turbo` on the first Lebanese clip once; compare transcript JSON sha256 (text and timestamps). Recorded, see §8.
5. Compute all §6 metrics with the instrument; write `metrics.json` and per-clip tables; write `SHA256SUMS` over all inputs and outputs.
6. Re-hash the instrument; it must equal step 1.

## 6. Metrics and thresholds (set NOW, never changed after lock)
### 6.1 Formulas
Tokens = whitespace split of the §6.2-normalised text. Alignment = Levenshtein (unit costs for substitution, deletion, insertion) between reference and hypothesis token sequences per clip, with the spelling-guide equivalence pairs treated as equal; `[؟؟]` stretches and their hypothesis words (by time overlap) removed from both sides first.
- `WER_LB(M)` = Σ_clips (S + D + I) / Σ_clips N_ref, pooled over the **Lebanese pool** (corpus-level, not a mean of per-clip WERs).
- `CER_LB(M)` = same, on character sequences of the normalised text **with spaces removed** (so clitic-spacing differences cost little), pooled over the Lebanese pool.
- `BE` = the set of boundary errors over all used words (§5.3) in the Lebanese pool: |ŝ − s| and |ê − e| in ms (ŝ, ê from M's word timestamps; s, e human). `P90_BE(M)` = 90th percentile of BE (linear interpolation, numpy default); `MED_BE(M)` = median of BE.
- `HALL_RATE(M)` = number of hypothesis words whose time midpoint lies inside a marked non-speech interval (§5.2.5), per 10 minutes of total clip audio (all clips, Lebanese + MSA).
- `RTF(M)` = Σ runtime / Σ audio duration over all clips.
- Diagnostics (no threshold): `WER_MSA(M)` on the MSA control; `WER_LATIN(M)` = WER restricted to reference tokens in Latin script (errors attributed by alignment: substitutions and deletions of Latin reference tokens / N Latin reference tokens); per-clip WER/CER; 95% clip-level bootstrap CI of `WER_LB` (10,000 resamples of clips, seed `20261123`); count of number-word vs digit mismatches.

### 6.2 Normalisation (applied identically to reference and hypothesis, in this order)
1. Unicode NFKC (maps Arabic presentation forms, e.g. U+FEFB "ﻻ", to base letters).
2. Remove Arabic diacritics and marks: U+0610–U+061A, U+064B–U+065F, U+0670, U+06D6–U+06ED; remove tatweel U+0640.
3. Alef: أ إ آ ٱ (U+0623, U+0625, U+0622, U+0671) → ا (U+0627).
4. Alef maqsura ى (U+0649) → ي (U+064A). Ta marbuta ة (U+0629) → ه (U+0647).
5. Hamza carriers: ؤ (U+0624) → و; ئ (U+0626) → ي; standalone ء (U+0621) removed. (Lebanese informal writing drops hamza; e.g. "رأيك"/"رايك", "شيء"/"شي" become equal.)
6. Digits: Arabic-Indic U+0660–U+0669 and Extended Arabic-Indic U+06F0–U+06F9 → ASCII 0–9.
7. Latin: Unicode casefold. Latin words are **not** transliterated; an English word that the ASR writes in Arabic script (e.g. "ايفون" for "iPhone") is a substitution, because the caption policy keeps Latin script.
8. Every character of Unicode general category P* or S* (including ، ؛ ؟ « » and U+061C ALM, which is category Cf and is also removed here), and every other Cf format character (U+200E, U+200F, U+200B–U+200D, U+2066–U+2069), is replaced by a space.
9. Collapse whitespace; strip.
Note: rule 5 maps "رئيس" to "رييس", not to the informal "ريس"; such pairs can only be made equal through the frozen variant list (§5.2.4).
Number words are not converted to digits or back; residual mismatches count as errors and are reported as a diagnostic.

### 6.3 Thresholds (PROPOSED by research-lead; the numbers marked † need Founder/Product confirmation before lock, O1. Once locked they never move.)
| Metric | Role | Pass | Kill | Between pass and kill |
|---|---|---|---|---|
| `WER_LB` | primary | ≤ 30% † | > 50% † | "neither": model usable only with mandatory human caption correction; no adoption as default without a new EXP |
| `P90_BE` | primary (A-02) | ≤ 150 ms | `MED_BE` > 150 ms | "neither": ASR text may be adopted, but cut timestamps need a forced-alignment stage (new EXP) |
| `CER_LB` | secondary | ≤ 15% † | > 30% † | reported; a kill here blocks adoption even if WER passes (sign of instrument or segmentation error to explain) |
| `HALL_RATE` | secondary | ≤ 2 words / 10 min | > 10 words / 10 min | adoption requires a hallucination filter on non-speech (new EXP) |
| `RTF` | secondary (cost) | ≤ 1.5 † | > 5.0 † | a kill does not reject the model: it means "transcribe locally and import the cached transcript" (E1 note), which needs Product acceptance |

Verdict per model: **PASS** iff `WER_LB` and `P90_BE` pass and no secondary metric is at kill (RTF kill excepted, as stated). **KILL** iff `WER_LB` is at kill. Otherwise **NEITHER**, with the reason per row. Whole-experiment verdict: PASS if ≥ 1 model PASSes; KILL if both models are KILL; otherwise NEITHER. **INCONCLUSIVE** if §5.2.7 reference reliability fails.

## 7. Analysis plan
- Point estimates decide the verdict (thresholds above). The clip-level bootstrap 95% CI of `WER_LB` is reported with every verdict; if the CI crosses the pass threshold, the claim states that explicitly ("pass on these clips; CI includes values above the threshold"). It does not change the verdict.
- **Selection rule (if both PASS):** adopt the model with lower `WER_LB`, unless the difference is ≤ 2.0 pp, in which case adopt the one with lower `RTF`. If only one PASSes, adopt it.
- Ties: exact ties in a metric go to the faster model. Outliers: no clip is removed after results are seen; any clip that is excluded for a §4/§5.2.6 reason is excluded for both models and listed.
- **Evidence level if PASS** with no validity-affecting deviation: **E2**, claim limited to "faster-whisper 1.2.1, model M, §3 parameters, CPU int8, these Lebanese-dialect clips, this normalisation". A validity-affecting but non-invalidating deviation downgrades one level (SOP-R3.3).
- Null and failed results are written in `EXP-001-results.md` with the same rigour, including per-clip tables and error examples (≤ 20 aligned error pairs per model, chosen by code: the first 20 by reference order).

## 8. Deviations policy and threats to validity
Any change from §5 is listed in the results, never hidden.

**Invalidating (result = INVALID):**
- A clip without a verified rights record, a held-out or `quarantine/` file, or a clip not listed in the locked §4.
- The reference transcriber or boundary annotator saw any ASR output of these clips; or the reference, spelling guide, non-speech file or boundary file was created or edited after any ASR output existed (commit order, checked by Assurance).
- The normalisation function fails any §6.2 test vector; any §3 parameter, model revision or the order of the §6.2 steps changed.
- The instrument hash at step 6 differs from step 1.

**Execution errors:** an error found before any metric has been computed allows up to 2 identical re-executions of §5.4, each logged. **Once any metric value has been seen, the result stands**; no re-run, no re-annotation, no new variant pairs.

**Non-invalidating, recorded:** library patch versions different from §3; non-identical determinism re-run (step 4; reported with the token-level diff; if the WER of the re-run differs by > 1 pp, the evidence level is downgraded one level); clip exclusions for §5.2.6.

**Threats to validity**
| Type | Threat | Mitigation |
|---|---|---|
| Construct | Lebanese has no standard orthography; spelling differences inflate WER without being errors. | Fixed §6.2 normalisation, a frozen ≤ 30-pair orthographic variant list made before ASR output exists, CER reported alongside WER. |
| Construct | WER weights all words equally; for captions and cuts, some errors (names, numbers, negation) matter more. | Error examples reported; a key-word weighted metric is out of scope (could be a successor EXP with Creative). |
| Construct | The reference is one person's transcription. | Optional second transcriber (§5.2.7) with a fixed INCONCLUSIVE rule. |
| Internal | Reference biased toward one model (the E1 method). | References made blind from audio only, frozen and hashed before any ASR run. |
| Internal | Boundary annotation is imprecise (± 10–20 ms) and subjective at coarticulated boundaries. | Same annotator rules for both models; threshold 150 ms ≫ annotation resolution; sampled words fixed before ASR runs. |
| Internal | Boundary metric only on correctly recognised words (survivorship): a model with more errors is measured on easier words. | Number of used words per model reported; low-n flag at < 20/30 per clip. |
| Internal | Nondeterminism through temperature fallback. | Seed set; determinism re-run (§5.4 step 4). |
| External | Few clips, few speakers, one dialect region; the Founder's own footage type is not yet known. | Claim limited to these clips; E3 replication on held-out at a later gate; dataset requirement tied to the declared footage type. |
| External | Forced `language="ar"` degrades English/French segments (known Whisper behaviour, E0). | `WER_LATIN` reported as a diagnostic; language handling for code-switching is a possible successor EXP. |
| External | Literature WERs for dialectal Arabic are on other dialects and datasets and do not transfer to our footage. | No literature number is used as a threshold; thresholds come from the product use (O1). |
