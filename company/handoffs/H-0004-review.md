## Rulings on the return's open questions
**(a) Rule 3, "no overlapping video clips" read as "the same source range is not reused".** **Acceptable for v0. No ADR and no Founder question are needed now.** v0 clips carry no timeline position and are concatenated in order, both in the schema description and in `build_command`. A timeline overlap is therefore impossible by construction, and the literal reading would make the rule vacuous. The same-source reading is the only one that changes behaviour. It is stricter (it fails closed), it is reversible (a validator rule, not a data format), and adjacent ranges are allowed (`test_rule3_adjacent_clips_same_source_do_not_overlap`). Conditions: (1) Engineering records this reading in the next ARCHITECTURE revision through a Proposed ADR, because the ARCHITECTURE text now says something different from what the code enforces. (2) If Creative (H-0007) wants intentional repeats such as a replayed punchline, that needs an explicit opt-in field. That is a schema change and needs an ADR. Tracked as F8.

**(b) Does `src/render/adapter.py` stay inside scope?** **Yes, it is inside scope.** Done-when #1 requires the existing render path to accept a valid v0 timeline. An input adapter is the minimal way to meet that. I checked the diff: `build_command`, `write_ass` and the filter-graph code are untouched. The only change in `render()` is validate → adapt → the same calls. "Rendering changes" (out of scope) means changes to how the output is produced, and none were made. However, the adapter silently drops capabilities, and one of them produces a validated-but-unrenderable timeline (F2). That consequence is a finding. The adapter's existence is not.
