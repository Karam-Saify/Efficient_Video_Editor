# E6 — Arabic caption rendering (FFmpeg/libass)

**Date:** 2026-11-21 · **Status:** PASS for FFmpeg/libass; Remotion not tested yet.
**Script:** `python experiments/e6_captions.py [--font "..."] [--reframe crop_center|fit_blur|fit_pad]`

## Setup
- Codespace, 2 vCPU, no GPU. ffmpeg 6.1.1 (Ubuntu) with libass (HarfBuzz + FriBidi).
- Synthetic 1920x1080 source → 3 clips → 1080x1920 output, 16.0 s, 7 caption lines.
- Fonts: Noto Naskh Arabic (apt `fonts-noto-core`), Amiri (`fonts-hosny-amiri`) also installed.
- Test lines: letter joining, lam-alef ligatures, full tashkeel, Lebanese dialect + `؟`,
  mixed RTL/LTR (`YouTube Shorts`, `30`), Arabic-Indic digits (`٢٥٠`) + trailing `!`, auto-wrap.

## Results
| Check | Result |
|---|---|
| Letter shaping / joining | Correct |
| Lam-alef ligatures (لا، لأ، إلا) | Correct |
| Tashkeel | Correct, marks placed on letters |
| Line wrap on vertical frame | Correct, 2 balanced lines |
| Mixed RTL/LTR order | **Wrong by default** → fixed (see below) |
| Output duration | Exactly 16.000 s = target |
| Render speed, `crop_center` | 13.8 s for 16 s (1.16× realtime) |
| Render speed, `fit_blur` | 25.4 s for 16 s (0.63× realtime) → ~95 s for a 60 s Short |

## Finding: base direction
With the ASS default `Encoding: 1`, libass lays out each line as an LTR paragraph:
`جرّبت YouTube Shorts لمدة 30 يوم` printed جرّبت on the left, and the `!` in
`السعر ٢٥٠ دولار فقط!` appeared on the right. Setting style `Encoding: -1` (libass auto base
direction) fixes both. The renderer now always writes `-1`.

## Decision
Use FFmpeg/libass for captions in Phase 1. Revisit Remotion only if we need animated
word-by-word captions or motion graphics that ASS `\k`/`\t` tags cannot handle.
Still to test: dialect lines from real transcripts, word-highlight karaoke (`\k`), bolder Shorts fonts
(e.g. Cairo, Tajawal from Google Fonts).
