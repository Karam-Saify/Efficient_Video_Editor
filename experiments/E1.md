# E1 — Arabic ASR quality (faster-whisper)

**Status:** harness ready, **blocked on real sample clips** in `samples/`.
**Script:** `python experiments/e1_asr.py samples/<clip>.mp4 --seconds 120 [--ref samples/<clip>_ref.txt]`

## Method
1. Take the first 2 minutes of each test clip.
2. Transcribe with `large-v3-turbo` and `large-v3` (CPU, int8, beam 5, VAD, word timestamps).
3. Hand-correct one model's output into `samples/<clip>_ref.txt`, then rerun with `--ref` to get WER/CER
   (normalized: no tashkeel/tatweel/punctuation, unified alef/ya/ta-marbuta). Transcripts are cached, so the rerun is instant.
4. Listen to `out/e1/<clip>/cut_test.<model>.wav` (every other 3-word group spliced) for clipped
   syllables, which would show timestamp drift.

## Pass criterion
Few errors on key words; cuts land cleanly on word boundaries. Also record RTF: if a 60 s clip takes
well over a few minutes on the Codespace, transcribe locally and commit the cached transcript.

## Pipeline smoke test (not a result)
espeak-ng synthetic Arabic + `tiny` model: code path, caching and word timestamps work; RTF ≈ 0.8.
Text quality was meaningless, as expected for robotic TTS on the smallest model.
